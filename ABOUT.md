# About

I work at the intersection of systems administration, platform engineering, and product development. My official role is system administrator; my project work also includes end-to-end application architecture, backend and frontend implementation, mobile clients, deployment, and production operations.

I am most effective when a task crosses boundaries: an application needs reliable identity, a realtime feature needs network-aware lifecycle handling, a database migration needs a rollback plan, or a production release needs evidence beyond “the container started.”

## Engineering approach

- Keep PostgreSQL or another explicit durable store authoritative; treat queues and caches as recoverable projections.
- Enforce authorization on the server and at the exact tenant/resource boundary.
- Make retryable operations idempotent and model lifecycle transitions explicitly.
- Separate source acceptance, deployment evidence, and runtime acceptance.
- Define success criteria and rollback triggers before changing production.
- Test restore paths, not only backup creation.
- Document unknowns as unknowns instead of silently converting them into assumptions.
